## Required real-radio checks

The build environment has no physical MeshCore Companion attached. Before treating this release as hardware-proven, run these checks against the intended firmware and a copied real profile:

1. Confirm automatic USB detection and forced `--device` connection.
2. Confirm app-start/device-query sequencing and returned device capabilities.
3. Sync a realistic contact list and verify person/repeater/room/sensor classification.
4. Pull multiple queued direct and channel messages until `NO_MORE_MESSAGES`.
5. Receive a waiting-message push while no TUI is attached.
6. Send a direct message and verify its exact expected ACK becomes `DELIVERED`.
7. Delay the ACK past the initial timeout and confirm the late ACK still resolves the same logical message.
8. Force a retry and confirm the sender timestamp/message identity is stable and the receiver does not see duplicate user-visible messages.
9. Enable stale-route reset and verify the full contact public key is used before retry.
10. Stop and restart the core while a message is awaiting ACK, then confirm a late ACK still resolves it.
11. Send long direct and channel messages containing Croatian text and emoji.
12. Deliver multipart segments out of order and with duplicates; confirm one logical message, one unread count, and one notification.
13. Send and receive ordinary short channel messages in public and private slots.
14. Create a private channel and verify the radio returns the same name and key.
15. Join an invitation generated by another client and import a QTC invitation in another client.
16. Rotate a key and confirm old invitations no longer decrypt new traffic.
17. Leave a channel and confirm the radio slot clears while local history remains.
18. Change device name and TX power, reboot the radio, and verify persistence.
19. Send zero-hop and flood advertisements and observe their intended reach from another node.
20. Export the radio's own contact card and import the resulting `meshcore://` URI in another client.
21. Apply the correct regional preset, reconnect, and verify the returned frequency, bandwidth, spreading factor, and coding rate.
22. Force stored-message sync from Settings.
23. Detach with `Ctrl+C`, receive traffic, and reconnect with `qtc`.
24. Keep a conversation open, receive a message for it, and verify desktop notification suppression plus an in-terminal banner.
25. Receive a message for a different conversation and verify desktop notification and sound behavior.
26. Use `F5` reconnect and physically unplug/replug USB under traffic.
27. Stop with `Ctrl+Q` twice and confirm `meshcli` can immediately open the device.
28. Run for several hours to check idle CPU, descriptor stability, memory growth, and redraw jitter.
29. Upgrade a copied real 2.3.1 profile and inspect contacts, aliases, groups, unread counts, settings, history, and retries.

## Reconstruction and protocol limits

- Source after QTC 2.3.1 was not preserved. This is a clean implementation of documented behavior, not a continuation of the missing internal code.
- The 2.3.1 SQLite schema did not store channel secrets. Migrated channel rows receive zero placeholders until refreshed from the radio.
- `QTC-LONG/1` multipart messages are application-level. Non-QTC clients may show the encoded physical parts rather than a reconstructed message.
- Companion firmware evolves. The adapter follows the documented Companion protocol, but the exact installed firmware remains the source of truth during hardware testing.
- Passing simulated, parser, database, and pseudo-terminal tests is not equivalent to completing RF and USB integration tests.

Official protocol references used by the adapter:

- https://docs.meshcore.io/companion_protocol/
- https://github.com/meshcore-dev/MeshCore/wiki/Companion-Radio-Protocol

## Asynchronous compose validation

The pseudo-radio integration test opens a live TUI conversation, leaves an unsent draft in the composer, injects an incoming radio message, and verifies that:

- the incoming text appears without leaving compose mode;
- the draft remains unchanged;
- the incoming banner is visible above the input line;
- typing continues after the asynchronous redraw.

The test uses the same Unix-socket and PTY paths as the release binary.
