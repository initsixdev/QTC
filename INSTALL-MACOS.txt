QTC TERMINAL 1.0.0 - MACOS INSTALLATION

There is no prebuilt macOS binary. Release packaging runs on Linux only, so a Mac
is installed from source. The build needs nothing beyond Apple's toolchain: the
macOS SDK already supplies SQLite 3.

1. Install the command line tools, if they are not present:

   xcode-select --install

2. Build and test:

   make
   make test

   The binary is named for the host, for example:

      build/qtc-macos-arm64
      build/qtc-macos-x86_64

3. Test without a radio:

   ./build/qtc-macos-arm64 --demo

4. Install for the current machine:

   sudo make install

   This places the binary at /usr/local/bin/qtc.

5. Run with automatic serial detection:

   qtc

6. Or force a device:

   qtc --device /dev/cu.usbmodem1101

USB ACCESS

List candidates:

   qtc --list-devices

macOS needs no device rule and no group membership. A connected MeshCore Companion
appears as a callout device:

   /dev/cu.usbmodem*
   /dev/cu.usbserial*
   /dev/cu.wchusbserial*
   /dev/cu.SLAB_USBtoUART*

and is readable and writable by the logged-in user. QTC deliberately ignores the
matching /dev/tty.* nodes: those block on carrier detect and are the wrong device
for a modem-style radio. Bluetooth and debug serial ports are never offered.

If nothing is listed while a radio is plugged in, the USB-serial bridge probably
needs its vendor driver. CH34x and CP210x bridges are the usual cases. Confirm the
device is visible to the system first:

   ls /dev/cu.*

OPTIONAL NOTIFICATIONS AND SOUND

Nothing needs installing. QTC uses osascript for desktop notifications, afplay for
the notification sound, and pbcopy for contact-card export, all of which ship with
macOS.

Notifications delivered through osascript are attributed to Script Editor. For a
dedicated QTC notification identity, install the optional helper, which QTC prefers
when present:

   brew install terminal-notifier

Set a custom notification sound with:

   export QTC_SOUND_FILE=/System/Library/Sounds/Submarine.aiff

QTC continues receiving and storing messages when optional helpers are absent.

LOCAL FILES

Data:

   ~/Library/Application Support is not used. QTC follows the XDG layout:

      ${XDG_DATA_HOME:-~/.local/share}/qtc-terminal/<profile>/qtc.db

Runtime socket and lock state:

   macOS does not define XDG_RUNTIME_DIR, so QTC creates a user-owned directory
   below /tmp instead. The socket is permission-restricted and the core verifies
   the connecting user's UID with getpeereid.

CORE LIFECYCLE

Ctrl+C or F8:
   detach this terminal; leave the background core and USB connection running

Ctrl+Q twice:
   stop the background core and release USB

Commands:

   qtc status
   qtc shutdown

PROFILES

   qtc --profile home --device /dev/cu.usbmodem1101
   qtc --profile field --device /dev/cu.usbmodem1401

Back up an existing 2.3.1 database before first use with real hardware.

TERMINAL NOTES

Terminal.app and iTerm2 both work. The interface uses UTF-8 box drawing and
measures names by terminal-cell width, so leave the terminal encoding at UTF-8.

macOS hardware validation is not complete. The build passes the full automated
suite, including sanitizers, but has not been run against a physical radio.

Check first that "qtc --list-devices" offers the connected radio and nothing else.
Exclusion of Bluetooth and debug serial ports has been confirmed; the positive
match against real hardware has not.
